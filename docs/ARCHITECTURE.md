# Chask — Architecture

## Overview

Chask is a monolithic server panel. No containers, no orchestration. Everything runs directly on the host OS for maximum efficiency on small VPS instances (~1GB RAM).

## Components

### 1. chaskd (Go daemon)

The daemon runs as root via systemd. It listens on a Unix socket and executes all privileged system operations.

```
/var/run/chaskd.sock (Unix socket, mode 0660, group: chask)
```

**Why a daemon?**
- The PHP panel should never run as root
- Separating concerns: panel handles UI/UX, daemon handles system ops
- The socket is local-only — no network attack surface
- Can be replaced/upgraded independently from the panel

**Responsibilities:**
- Create/delete Linux users and directories
- Generate and reload Caddy configs
- Manage PHP-FPM pools
- Execute MySQL admin commands
- Manage UFW firewall rules
- Handle DNS zone files
- Run backup/restore operations
- Report system metrics

**Security model:**
- Socket permissions restrict access to the `chask` group
- Every input is validated before execution
- Commands use `exec.Command` with argument arrays (no shell interpolation)
- Allowlisted operations only — the daemon cannot run arbitrary commands

### 2. Panel (CodeIgniter 4)

The web panel runs as a regular user (`chask`) via PHP-FPM behind Caddy on port 2083.

**Responsibilities:**
- Authentication (session-based)
- UI for all management operations
- Communicates with daemon via Unix socket
- Stores panel-specific data in its own MySQL database (`chask_panel`)
- Activity logging

**Communication with daemon:**
```php
// app/Libraries/ChaskClient.php
$client = new ChaskClient('/var/run/chaskd.sock');
$result = $client->send('sites.create', [
    'domain' => 'example.com',
    'php_version' => '8.4',
]);
```

### 3. Caddy (Web Server)

Serves both the panel and user sites. One Caddyfile imports per-site configs.

```
/etc/caddy/Caddyfile              ← Main config (panel + global settings)
/etc/caddy/sites.d/*.caddy        ← Per-site configs (generated by daemon)
```

**Per-site config example:**
```caddyfile
example.com {
    root * /home/example-com/public_html
    php_fastcgi unix//run/php/example-com.sock
    file_server
    log {
        output file /home/example-com/logs/access.log
    }
}
```

### 4. PHP-FPM

One FPM pool per site for isolation. Each pool runs as the `chask` user (v1) or as the site's Linux user (v2+).

```
/etc/php/8.4/fpm/pool.d/example-com.conf
```

### 5. MySQL

Shared MySQL instance. The daemon creates databases and users with per-database permissions.

```sql
CREATE DATABASE `example_com_db`;
CREATE USER 'example_com'@'localhost' IDENTIFIED BY 'generated_password';
GRANT ALL ON `example_com_db`.* TO 'example_com'@'localhost';
```

## Directory Structure on Server

```
/opt/chask/                      ← Installation root
├── daemon/chaskd                ← Go binary
├── panel/                       ← CI4 application
├── config/
│   ├── caddy/sites.d/           ← Generated Caddy configs
│   ├── php/pools.d/             ← Generated FPM pool configs
│   └── dns/zones.d/             ← Generated DNS zones
├── backups/                     ← Backup storage
└── logs/                        ← Panel and daemon logs

/home/{site-name}/               ← Per-site directory
├── public_html/                 ← Document root
├── logs/                        ← Site access/error logs
└── tmp/                         ← PHP sessions, uploads
```

## Systemd Services

```ini
# /etc/systemd/system/chaskd.service
[Unit]
Description=Chask Daemon
After=network.target mysql.service caddy.service

[Service]
Type=simple
ExecStart=/opt/chask/daemon/chaskd
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

## Communication Protocol

All communication between panel and daemon uses JSON over Unix socket.

### Request format
```json
{
  "action": "module.operation",
  "data": { }
}
```

### Response format
```json
{
  "status": "ok|error",
  "data": { },
  "error": "message if status is error"
}
```

### Available actions (v1)

| Action | Description |
|--------|-------------|
| `system.health` | Daemon health check |
| `system.metrics` | CPU, RAM, disk, uptime |
| `sites.list` | List all sites |
| `sites.create` | Create site (vhost + FPM pool + dirs) |
| `sites.update` | Update site config |
| `sites.delete` | Delete site |
| `databases.list` | List MySQL databases |
| `databases.create` | Create database + user |
| `databases.drop` | Drop database + user |
| `databases.import` | Import SQL file |
| `databases.export` | Export database |
| `php.versions` | List installed PHP versions |
| `php.install` | Install PHP version |
| `firewall.list` | List UFW rules |
| `firewall.allow` | Add allow rule |
| `firewall.deny` | Add deny rule |
| `firewall.delete` | Remove rule |
| `ssl.status` | Certificate status per site |
| `dns.zones` | List DNS zones |
| `dns.records` | CRUD DNS records |
| `backups.list` | List available backups |
| `backups.create` | Create backup |
| `backups.restore` | Restore from backup |
| `backups.schedule` | Set backup schedule |
